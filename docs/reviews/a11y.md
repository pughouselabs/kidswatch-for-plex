# Accessibility audit (WCAG 2.2 AA)

Audit of KidsWatch for Plex at commit `492324f`, run against the local preview
(`python -m tests.dev_server`, fake Plex and sample data). Read-only for code: every
finding below names the page, the file and line, and a suggested fix. Nothing was changed
in the app.

## How it was tested

- **axe-core 4.14.0** (via `npx`/Playwright, Chromium) on 18 page states, each in light and
  dark color schemes, with the `wcag2a`, `wcag2aa`, `wcag21a/aa`, `wcag22aa` and
  `best-practice` rule sets. The app's CSP blocks injected scripts, so the test browser ran
  with CSP bypass; the app itself was not changed.
- **Keyboard walk** with Tab and Shift+Tab on every page at 1280, 800 and 390 px wide:
  focus order, a visible focus style on each stop, and whether the focused element is hidden
  behind sticky or fixed content.
- **Touch targets** measured at 390 px wide with both a touch (coarse) and mouse (fine)
  pointer, against 2.5.8 (24 by 24 px, or enough spacing).
- **Reflow** at 320 px and the **text spacing** override from 1.4.12.
- **Non-text contrast** computed from the design tokens in `app/static/style.css`.
- **Dynamic flows** scripted in the browser: title details dialog, "Change all" confirm,
  Block from history, Pause with Undo, and a failed "Remove child" to see how errors land.
- Pages: `/`, `/help`, `/link/<token>`, `/home`, `/kids/new`, `/kids/1` (active),
  `/kids/1/schedule`, `/kids/1/activity`, `/kids/1/settings`, `/kids/1/titles`, `/kids/2`
  (not connected), `/kids/2/settings`, `/requests`, and `/admin` with all four tabs (owner).
  `/verify` redirects in the preview, so it was reviewed from the template only.

Not covered: a real screen reader pass (NVDA, VoiceOver, TalkBack). The live region and
table findings below are based on how those readers usually behave and should be confirmed
on a device before closing them.

## What is already good

- `lang="en"`, unique page titles on most pages, a working "Skip to content" link, and
  `header`, `nav` (labeled), `main` and `footer` landmarks on every page.
- One `h1` per app page, `h2` per card, no skipped levels on the kid pages.
- All icons are `aria-hidden` and icon-only buttons have names ("Sign out", "Close",
  "Dismiss", "Remove Casey").
- Native `<dialog>` for title details and confirms: focus moves in, stays in, Escape closes,
  and focus returns to the poster that opened it.
- Menus close on Escape and return focus to their button.
- Every page reflows at 320 px with no sideways scrolling.
- `prefers-reduced-motion` turns off every transition and animation (`style.css:510`), and
  the landing page pulse only runs when motion is allowed (`style.css:788`).
- Text contrast passes axe in both light and dark (one exception, finding 3).
- Touch targets pass 2.5.8 almost everywhere, and coarse pointers get 44 px buttons
  (`style.css:467`).

## Findings, ranked

Severity: **High** = blocks or seriously hinders a group of users and fails a WCAG A/AA
criterion. **Medium** = fails or very likely fails a criterion with a workaround. **Low** =
minor failure, edge case, or best practice.

### High

**1. Focus ring is too faint to see (1.4.11 Non-text Contrast, 2.4.7 Focus Visible)**
- Pages: all. Links, buttons, tabs, summaries, switches.
- Where: `app/static/style.css:34` (`--focus: 0 0 0 3px rgba(194, 65, 12, .3)`),
  `style.css:72` (dark), applied by `style.css:98`.
- Problem: the ring is the brand color at 30 to 35% opacity. Measured contrast against the
  card: **1.57:1 light, 1.90:1 dark**; the minimum is 3:1. Keyboard users with low vision
  lose track of where they are. Inputs are fine because they also get a solid brand border
  (`style.css:205`).
- Fix: use a solid ring, for example
  `--focus: 0 0 0 2px var(--surface), 0 0 0 4px var(--brand)` (brand is 5.18:1 light,
  6.87:1 dark). Or switch to `outline: 2px solid var(--brand); outline-offset: 2px` on
  `:focus-visible`, which also survives Windows high-contrast mode where box-shadow is
  removed.

**2. Errors disappear after 8 seconds and are not tied to the field (3.3.1 Error
Identification, 4.1.3 Status Messages, 2.2.1 Timing Adjustable)**
- Pages: every form that can fail on the server: Remove child, Add a child, Settings,
  Schedule, Requests, Admin replies, Admin code check.
- Where: errors are flashed and redirected (`app/main.py:583, 673, 900, 904, 944, 948, 1062,
  1223, 1384`), rendered as a toast (`app/templates/base.html:56-58`), and removed by
  `app/static/app.js:97-100` after 8 s.
- What happens (tested on Remove child with the wrong name): the page reloads, focus is on
  `<body>`, the "Remove Kid2" section is closed again, the field has no `aria-invalid`, and
  the only message is a toast at the bottom of the screen that is gone 8 s later. The toast
  is already in the DOM when the page loads, so most screen readers never announce it (live
  regions only speak changes made after load). On Schedule and Settings the redirect also
  throws away what the parent typed.
- Fix:
  - Do not auto-dismiss error toasts; keep the Dismiss button.
  - Render form errors next to the field: `aria-invalid="true"` plus
    `aria-describedby` pointing at an inline message, and reopen the `details` (Remove) the
    error belongs to.
  - For the toast itself, insert the flash text into the live region from `app.js` a moment
    after load (or use `role="alert"` for errors) so it is spoken.
  - Longer term, re-render the form with the posted values instead of redirecting on error.

**3. Dark mode error toast text fails contrast (1.4.3 Contrast Minimum)**
- Pages: any page showing an error toast, dark scheme.
- Where: `app/static/style.css:192` (`.toast.error { background: var(--stop); color: #fff; }`).
- Problem: in dark mode `--stop` is `#ff8a85`, so white text measures **2.28:1** (needs
  4.5:1). axe did not catch it because no toast was on screen during the scan; confirmed by
  reading the rendered colors.
- Fix: in dark mode use dark text on the light red (`color: #14100c` gives about 9:1), or
  keep a deep red background such as `#c3262e` for the toast in both schemes.

**4. Undo buttons vanish before keyboard and screen reader users can reach them (2.2.1
Timing Adjustable)**
- Pages: Overview and My kids (Pause, Add time, Pause everyone), Titles (Change all), Watch
  history (Block).
- Where: `app/static/app.js:99` (server toasts with Undo: 8 s), `app.js:119` (script toasts
  with Undo: 8 s). The toast container is the last thing in the page
  (`base.html:56`).
- Problem: Undo is the safety net for a mis-tap, but it sits after the footer in tab order
  (about 25 to 40 Tab presses away) and is removed after 8 s (measured 8045 ms). There is no
  way to extend the time, and hovering or focusing does not pause it.
- Fix: pause the dismiss timer while the toast has hover or focus, do not auto-dismiss
  toasts that have an action (or allow at least 20 s and let users extend it), and move focus
  to the Undo button, or announce "Press Undo to reverse" with a keyboard shortcut. Keeping
  the Undo option on the page itself (for example a "Paused until 7:39 PM, Undo" line in the
  Today panel) avoids the timing problem entirely.

**5. Week chart hides its numbers from screen readers (1.1.1 Non-text Content)**
- Pages: Overview (`/kids/{id}`), Activity.
- Where: `app/templates/_week_chart.html:1-4`.
- Problem: the SVG has `role="img"` and `aria-label="Screen time for the last 7 days"`.
  `role="img"` hides everything inside, including the good per-day `<title>` text the server
  already writes ("Monday: 2 hr 20 min of 2 hr"). A screen reader user hears only the label,
  with no values and no way to tell which days went over the limit. The `<title>` tooltips
  also only appear on mouse hover.
- Fix: keep `role="img"` but add a text version next to it, for example a visually hidden
  list built from the same data:
  `<ul class="visually-hidden">{% for b in chart.bars %}<li>{{ b.title }}{% if b.cls == 'over' %}, over the limit{% endif %}</li>{% endfor %}</ul>`
  and point the SVG at it with `aria-describedby`. Then drop the per-bar `<title>` or keep it
  for mouse users.

### Medium

**6. Focused items slide under the sticky header (2.4.11 Focus Not Obscured, new in 2.2)**
- Pages: every page at widths above 720 px; worst on Titles, where a second sticky toolbar
  sits under the header.
- Where: `app/static/style.css:101` (sticky header), `style.css:328` (sticky titles
  toolbar). There is no `scroll-padding-top` anywhere.
- Measured with Shift+Tab: elements **fully hidden** behind the header on Overview ("All
  titles", "Schedule" and the kid tabs at 800 px), Settings (Save, the first age level, the
  breadcrumb), Schedule, Help (FAQ summaries) and Admin Security. On Titles, 10 to 14 posters
  and buttons per pass were partly or fully covered by the toolbar.
- Fix: `html { scroll-padding-top: 76px; }` and, on the titles page,
  `html:has(.toolbar) { scroll-padding-top: 150px; }` (match the measured toolbar height).
  The phone layout drops the sticky header (`style.css:539`), but the sticky Save bar on
  phones (`style.css:517`) needs the same treatment at the bottom:
  `scroll-padding-bottom: 80px` inside that media query.

**7. Links inside sentences are only told apart by color (1.4.1 Use of Color)**
- Pages: all app pages (footer "Suggest a feature" / "ask for access"), Settings ("Titles",
  "Ask Admin to add them", "Connect it"), Connect card ("plex.tv/sign-up"), Help, Overview
  ("Review them").
- Where: `app/static/style.css:81` (`a { color: var(--brand); text-decoration: none; }`).
- Problem (axe `link-in-text-block`, serious): link vs surrounding text is **2.07:1** against
  body text and **1.14:1** against hint text in light mode, 1.60:1 and 1.03:1 in dark. The
  minimum without an underline is 3:1.
- Fix: underline links that sit in running text, for example
  `p a, .hint a, .step-text a, .footer-ask a, .faq a { text-decoration: underline; text-underline-offset: 2px; }`
  and keep the current style for nav, tabs, buttons and cards.

**8. Switch "off" state and input borders are hard to see (1.4.11 Non-text Contrast)**
- Pages: Settings (Libraries), Schedule (Any time, Friday, Sunday), Admin Parents; every text
  field and select.
- Where: `app/static/style.css:224` (switch track `--line-strong`), `style.css:202` (input
  border `--line-strong`), tokens at `style.css:18` and `:57`.
- Problem: `--line-strong` on the card is **1.58:1 light, 1.48:1 dark**. An "off" switch is a
  pale gray pill with a white knob (white knob on the track: 1.58:1), so its shape and state
  are hard to make out. Text field outlines have the same low contrast.
- Fix: darken the switch track to `--muted` (5.08:1 light, 6.07:1 dark against the card), or
  give the off track a 1px `--muted` border. For inputs, a border color around `#8f857a`
  light / `#6f655b` dark reaches 3:1.

**9. Radio groups have no group label (1.3.1 Info and Relationships)**
- Pages: Add a child ("What can they watch?"), Requests ("What do you need?"), Settings
  ("What Kid1 can watch").
- Where: `app/templates/kid_new.html:12-13`, `app/templates/requests.html:22-23`,
  `app/templates/kid_settings.html:24`.
- Problem: the question is a plain `<span class="label">`, so screen readers announce
  "Little kids, radio button, 1 of 4" with no question. The Color swatches get this right with
  `role="radiogroup" aria-labelledby` (`kid_settings.html:13`).
- Fix: wrap each set in `<fieldset>` with a `<legend>`, or reuse the swatch pattern:
  `<div class="choice-list" role="radiogroup" aria-labelledby="level-label">` with an id on
  the label span.

**10. Schedule fields share the same names (1.3.1, 2.4.6 Headings and Labels)**
- Page: Schedule.
- Where: `app/templates/kid_schedule.html:44-46`.
- Problem: the weekday and weekend rows each have fields named "From", "Until" and "Any
  time". The row title ("Weekdays", "Weekends") is a plain `div`, so a screen reader user
  hears "From, time" twice with no way to tell the rows apart.
- Fix: give the row a group label:
  `<div class="sched-row" role="group" aria-labelledby="{{ prefix }}-day">` with
  `<div class="day" id="{{ prefix }}-day">`, or make the hidden labels say "Weekends from",
  "Weekends until", "Any time on weekends".

**11. Titles grid: state and controls depend on sight (1.3.1, 2.4.6, 2.5.3 Label in Name)**
- Page: Titles.
- Where: `app/templates/kid_titles.html:57-67`, `app/static/app.js:229-236`.
- Problems:
  - Whether a title is visible to the child is shown only by the dimmed poster and an
    `aria-hidden` check or X (`kid_titles.html:60`). A screen reader user has to infer it from
    whether the button says Block or Allow.
  - The Block/Allow button is named just "Block" or "Allow" on page load (30+ identical
    buttons); only after the first click does the script set "Allow Button Parade".
  - "Your pick · Undo" (`:65`) does not say which title, and is only 14 px tall (passes 2.5.8
    on spacing, but is a small target).
  - Poster buttons with a "New" badge are named "Details for X" while the visible text says
    "New" (axe `label-content-name-mismatch` on 4 posters).
- Fix: render the names on the server so they are right from the start:
  `aria-label="{{ 'Block' if r.visible else 'Allow' }} {{ r.title }}"`; add visually hidden
  state text in the tile body ("Can watch" / "Hidden"); name the reset button
  "Your pick · Undo<span class="visually-hidden"> for {{ r.title }}</span>"; and replace the
  poster `aria-label` with visually hidden text so the "New" badge joins the name
  ("Details for Cloud Garden, New").

**12. Focus is lost after some actions (2.4.3 Focus Order)**
- Pages: Titles ("Change all"), Overview and Activity (Block from history).
- Where: `app/static/app.js:355` closes the menu before the confirm opens, so when the
  confirm closes focus returns to a hidden button and ends up on `<body>` (tested: Escape on
  the confirm leaves focus on BODY). `app.js:406-410` disables the Block button after a
  click, which drops focus to `<body>`; its `aria-label` still says "Block X for Kid1" while
  the text now says "Blocked".
- Fix: after the confirm closes, move focus to the "Change all" summary. For quick Block,
  keep the button enabled with `aria-disabled="true"` (or swap it for the "Blocked" span and
  focus the Undo action), and update the `aria-label` to "X is blocked".

**13. Kid cards on My kids have no headings (1.3.1, 2.4.6)**
- Page: My kids.
- Where: `app/templates/home.html:25-29` and the card footer links at `:46`.
- Problem: each kid is a `<section>` with no heading and no name; the kid's name is a plain
  link. Screen reader users cannot jump between kids by heading or region, and the footer
  links read "Overview, Titles, Schedule" three times per page without saying for whom. At
  390 px with a mouse pointer the footer links are 20 px tall and too close together
  (2.5.8 fails on spacing; touch pointers get padding and pass).
- Fix: `<h2 class="name"><a href="/kids/{{ kid.id }}">{{ kid.name }}</a></h2>` and
  `<section ... aria-labelledby="kid-{{ kid.id }}">`; add visually hidden " for {{ kid.name }}"
  to the footer links; give `.card-footer.row a` the coarse-pointer padding at all widths.

**14. Admin "Can use the site" switches submit on change (3.2.2 On Input)**
- Page: Admin, Parents tab.
- Where: `app/templates/admin.html:121`, `app/static/app.js:203`.
- Problem: flipping the switch submits the form and reloads the page, with no warning. A
  keyboard or screen reader user exploring the table can turn a parent off by pressing Space
  once, then lands at the top of a reloaded page.
- Fix: add a visible hint above the table ("Changes save right away"), which satisfies 3.2.2,
  and after reload put focus back on the switch that changed (for example with a `#parent-ID`
  anchor and `tabindex="-1"` row).

### Low

**15. Status text is cut off on phones (1.4.10 Reflow, 1.4.12 Text Spacing)**
- Pages: My kids, Overview, at 390 px and below.
- Where: `app/static/style.css:580` (`white-space: nowrap; text-overflow: ellipsis`).
- Problem: "Maple Club: Camping on Living Room TV" is clipped to "Maple Club: Camping on Li..."
  (274 px of text in 232 px). Screen readers get the full text, sighted users do not. With
  the 1.4.12 spacing override the Schedule page also overflows by 8 px at 320 px.
- Fix: let the status line wrap (`white-space: normal`) on narrow screens.

**16. Pages without an `h1`, and generic titles (1.3.1, 2.4.2 Page Titled, 2.4.6)**
- Pages: Connect link (`/link/<token>`, axe `page-has-heading-one`), Connected, message
  pages, Waiting, Admin sign-in code.
- Where: `app/templates/link.html:8`, `link_done.html:8`, `message.html:9`,
  `waiting.html:6`, `verify.html:7` all start at `h2`. `waiting.html` has no `title` block, so
  the tab just says "KidsWatch for Plex". All four Admin tabs share the title "Admin".
- Fix: change those first headings to `h1`, add
  `{% block title %}Waiting for approval · KidsWatch for Plex{% endblock %}`, and include the
  tab name in the Admin title ("Parents · Admin · KidsWatch for Plex"). Optional: give the
  Titles page a visually hidden `h2` ("Movies and shows") so the grid is reachable by heading.

**17. Live region quirks (4.1.3 Status Messages)**
- Where: `app/templates/base.html:56` puts `role="status"` toasts inside an
  `aria-live="polite"` container, which some readers announce twice. Success toasts from the
  server have the same load-time problem as finding 2. The Today panel
  (`app/templates/_today.html:3`, `app.js:166-171`) updates every 15 s without announcing,
  which is fine, but `app.js:153` reloads the whole page when the state flips between paused
  and not paused, which resets focus and scroll for anyone mid-task.
- Fix: keep one live container and drop `role="status"` from each toast. Replace the reload
  with an in-place update of the Pause/Resume buttons, or skip the reload while focus is
  inside the panel.

**18. Single-key "/" shortcut (2.1.4 Character Key Shortcuts)**
- Page: Titles.
- Where: `app/static/app.js:75-81`.
- Problem: "/" jumps to search whenever focus is not in a text field, including while a
  button is focused. 2.1.4 asks for a way to turn it off or remap it, or a modifier key.
- Fix: also accept Ctrl/Cmd+K and only take "/" when `document.activeElement === document.body`,
  or document it and add an off switch. Low impact, since "/" is rarely typed by speech
  tools.

**19. Swatch and badge names (1.1.1, 1.3.1)**
- Where: `app/templates/kid_settings.html:15` names the colors "Color 1" to "Color 6";
  `_kid_header.html:12` shows a new-titles count whose meaning is only in a `title` tooltip;
  `admin.html:98` hides the sync error in a `title` attribute (mouse only).
- Fix: name the colors (Orange, Green, Blue, Purple, Pink, Teal, matching
  `style.css:177-178`); add `<span class="visually-hidden"> new</span>` to the tab count as
  the main nav already does (`base.html:27`); show the sync error as text or in a
  `details` element.

**20. Smaller items**
- **Switch hints not linked** (`kid_schedule.html:55-58`, `kid_settings.html:43-44`): the
  explanation under each switch is not read with it. Add `aria-describedby` to the input.
- **Required fields** (`kid_new.html:11`, `requests.html:40`, `kid_settings.html:11`): no
  visible "required" marker. Most forms have one or two fields, so this is minor; add
  "(required)" to the label if more fields appear.
- **Admin tables on phones** (`style.css:444`, `:549`): table cells are switched to
  `display: block/grid`, which makes Safari/VoiceOver drop the table roles. Add
  `role="table"`, `role="row"`, `role="cell"` explicitly, or test with VoiceOver and keep as
  is if it reads well. The Kids and Parents tables also lack a `<caption>` or heading.
- **Repeated generic names** in Admin requests: every reply box is "Reply" and every button
  "Mark done" / "Decline" (`admin.html:37-47`). Add the requester's name visually hidden
  ("Reply to Sam").
- **Kid tab nav name** (`_kid_header.html:10`): `aria-label="Kid1"` announces as
  "Kid1 navigation". "Kid1 sections" is clearer.
- **Toast Dismiss button** is 22 by 22 px (`style.css:193`); passes on spacing, but 24 px
  minimum is safer.
- **New tab links** (`_connect.html:12`, `help.html:11, 16`) have no "opens in a new tab"
  hint, unlike the Requests button which does (`requests.html:14`). Add the same visually
  hidden text.
- **Choice descriptions hidden on phones** (`style.css:541` and `:566`,
  `.choice:not(:has(input:checked)) .desc { display: none; }`): unchecked options lose their
  explanation at 520 px and below for everyone. Consider showing them collapsed instead.
- **Chart bars** "Earlier" fill is 1.85:1 light / 2.28:1 dark against the card. Every bar has
  a printed value, so this passes, but finding 5's text version makes it moot either way.

## Suggested order of work

1. Findings 1, 3 and 7 are CSS-only (`style.css`) and fix the widest problems: focus ring,
   dark error toast, and underlined links.
2. Finding 6 is a two-line CSS change (`scroll-padding`).
3. Findings 2 and 4 (errors and Undo timing) need `app.js` plus template work and are the
   biggest real-world risk.
4. Finding 5 (chart text) and findings 9 to 13 are template-only edits.
5. Re-run axe (both schemes) and a short VoiceOver or NVDA pass on Overview, Titles and
   Schedule afterward.
